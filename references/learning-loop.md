# 学习闭环

## 先定义范围

确定人物、关系场景、私人工作目录、轮次上限及评估目的。按会话或日期划分约75%训练，其余开发/测试。记录实际分组数和消息占比；分组比例不等于消息比例。已有档案看过的数据不能重新称为全新测试集。

## 证据转成档案

从完整消息组及其前文学习：回复哪件事、为什么转移注意、会不会继续自己的叙述、何时问具体问题、拒绝、开玩笑、确认或不回应。分别学习每人的表达分布，同时寻找例外。引用是线程线索，不能把引用者误当原话作者。

保存规则的证据ID及反例，不把一种情境里的行为写成永久人格。提及活动的日期覆盖率可报告，但区分已做、正做、计划、习惯，注明漏检。转贴的长文章和提示词不能直接当自然说话风格。

## 实际迭代

冻结初版 → 在未看后续的前提下生成 → 揭晓开发答案或用户反馈 → 定位具体偏差 → 回真实训练材料核实 → 小幅修改 → 新上下文复测。

“像聊天”与“像这个人”分开判断。模型容易把双人模拟写成整齐的小作品；不要用错字、随机跳题、消息数配额来补救。让每人保留自己的状态和注意力，也允许普通的单句回应。

历史记忆可能正确被检索，却被错误解释；审核谁说的、是否是计划、态度是否被擅自补全。功能调用成功不代表模仿更好。

每轮记录数据范围、读取规模、生成条件、完整预测、反馈、修改及失败。仅依据评审的“更像”而没有真实训练证据时，保留为待验证假说。最终测试一旦用于修订，降级为开发材料。
